# Render deployment

The Git repository root is `AICaller/`. Keep `render.yaml` at that root; Render's
Docker build context must include `apps/`, `packages/`, `scripts/`, and `deploy/`.
The current monorepo layout is intentional:

```text
AICaller/
├── apps/
│   ├── server/          # Fastify API, WebSockets, and migrations
│   └── web/             # React dashboard
├── packages/shared/     # Types and schemas used by both apps
├── scripts/             # Local and database tooling
├── deploy/render/       # Render startup and this guide
├── Dockerfile            # Multi-stage production image
├── pnpm-lock.yaml        # Reproducible dependency install
└── render.yaml           # Render Blueprint
```

## Deploy for a live calling test

1. Push the `AICaller/` Git repository to GitHub, including `render.yaml`.
2. Create a free PostgreSQL project in Neon and copy its **direct** connection
   string, with SSL enabled. `pg-boss` needs a persistent PostgreSQL session;
   its transaction-pool connection string is unsuitable here.
3. In Render, choose **New > Blueprint**, select the GitHub repository and
   branch, and use its root `render.yaml`. The Blueprint creates one free Docker
   web service. For a new Blueprint it prompts for `DATABASE_URL`,
   `SEED_ADMIN_EMAIL`, `SEED_ADMIN_PASSWORD`, `GROQ_API_KEY`, `GNANI_STT`,
   `GNANI_TTS`, `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, and
   `TWILIO_PHONE_NUMBER`. Use a unique admin password of at least 12 characters.
   Render cannot read your local `.env` file.
   **For an existing Blueprint**, add the five new Gnani and Twilio variables in
   the web service's **Environment** page: Render does not prompt for new
   `sync: false` variables when an existing Blueprint syncs.
4. Let the deployment finish. The startup script applies the idempotent SQL
   migration before the app opens. The app creates the first admin account on
   startup. Visit the Render URL and log in with the seed credentials.
5. Check `https://<your-service>.onrender.com/readyz`, then open **Settings >
   Connections**. The dashboard should show live mode and all providers
   configured. A configured label means credentials are present, not that a
   provider has been tested successfully.
6. Use a consented, verified test phone number in international format (for
   example, `+91...`). Confirm consent and place one HR test call inside the
   configured Asia/Kolkata calling window. Overnight windows are supported. A Twilio trial account
   can call only verified destinations. Inspect the call result and Twilio
   debugger if no ring arrives.

`PUBLIC_BASE_URL` is wired to Render's own HTTPS URL. `SESSION_SECRET` and
`WEBHOOK_SIGNING_SECRET` are generated by Render. Set all secrets in Render's
dashboard; never commit `.env` or `.env.local`.

This Blueprint starts with `MOCK_MODE=false`, so calls can reach Twilio once
the required credentials are set. The app uses Render's public HTTPS URL for
Twilio callbacks unless `TWILIO_WEBHOOK_BASE_URL` overrides it. Provider calls
may consume credits. Render Free services sleep after idle time, which can delay
or interrupt queued calls and background jobs. Wake the service in your browser
before a one-off test; use an always-on service for reliable scheduled calls.
